# Step P0 — Setup and scaffold (explained for a beginner)

This is the note you can read before the review. It explains every file and function that
step P0 created, in plain English, with a tiny number example for each idea.

---

## 1. What this step does, in five sentences

1. We install Python 3.12 and give this project its own private copy of Python, called a
   virtual environment, so the project's libraries never clash with anything else on the
   laptop.
2. We install the five libraries the project is allowed to use: ultralytics (which contains
   YOLOv8, the person detector), opencv-python (video frames), numpy (number arrays),
   fastapi (the web server) and uvicorn (the program that runs that server).
3. We create the empty skeleton of the app: a folder for code (`app/`), for the web page
   (`static/`), for helper scripts, for tests, for videos, for outputs, for evidence
   photos, and for these notes.
4. We write `app/config.py`, the single file that holds every tunable number and every
   file path, so no other file has to hide a "magic number" inside a function.
5. We prove it works: a check script prints the library versions, prints `CONF = 0.35`,
   loads the YOLO model once, and then we make the first Git commit so every later step can
   be undone.

The goal of P0 is **not** to detect people yet. The goal is: "the ground is solid".

---

## 2. Why we installed Python 3.12 (a real decision we made)

The laptop's default Python was **3.13**. The project rules allow **Python 3.10, 3.11 or
3.12**, because the computer-vision libraries are tested on those versions. Instead of
risking a 3.13-only bug during a two-day build, we installed Python **3.12.10** next to
3.13 (the new install does not remove the old one) and used it to create the project's
environment.

Tiny example: `py -0p` lists the interpreters.

```
 -V:3.13 *   C:\...\Python313\python.exe
 -V:3.12     C:\...\Python312\python.exe
```

The `*` means 3.13 is still the default for the rest of the laptop. This project simply
says `py -3.12` when it needs its own interpreter.

## 4. `app/config.py` — every constant, in plain words

A "constant" is a name that never changes while the program runs, like a label on a jar.

### 4.1 Model and detection settings

| Name | Value | Plain meaning | Tiny number example |
| --- | --- | --- | --- |
| `MODEL_PATH` | `"yolov8n.pt"` | File name of the YOLOv8 **nano** weights (the small, CPU-friendly version) | The first time it runs, ultralytics downloads about 6 MB into the project folder |
| `CONF` | `0.35` | Minimum confidence for a detection to be believed | YOLO says "person, 0.30" → dropped; "person, 0.90" → kept; "0.35" → kept (rule is "at least") |
| `IMGSZ` | `640` | The square size, in pixels, that the model sees | A 1920×1080 frame is squeezed to 640×360 for the model; coordinates are scaled back afterwards |
| `FRAME_WIDTH` | `640` | Width we resize frames to for drawing and streaming | 1280×720 becomes 640×360 |
| `STRIDE` | `2` | Run the detector on every 2nd frame | A 30 fps clip gives 15 detections per second instead of 30, roughly halving CPU work |

Why `CONF` matters in one sentence for the panel: *"0.35 is a balance — low enough to see
people at the back of a crowd, high enough that a chair is not counted as a person."*

### 4.2 Capacity alert timing

| Name | Value | Plain meaning | Tiny number example |
| --- | --- | --- | --- |
| `ON_DELAY` | `3.0` s | The zone must stay **over** capacity this long before we alert | Counts at t = 0,1,2,3 s are 11,11,10,11 → at 3 s it is over → alert |
| `OFF_DELAY` | `5.0` s | The zone must stay **at or under** capacity this long before we clear | Counts at t = 10…15 s are 9,10,9,9,9,9 → cleared at 15 s |

This pair is the project's extra feature, **debounce**: it stops the alarm from flickering
when one person steps on and off the edge of a zone.

### 4.3 Analytics and tracking

| Name | Value | Plain meaning | Tiny number example |
| --- | --- | --- | --- |
| `NEAR_RATIO` | `0.8` | Two people count as "too close" if the gap between them is under 0.8 of a box width | Box width 50 px → a gap under 40 px counts as a bottleneck |
| `HEAT_DECAY` | `0.995` | Each frame multiplies the heatmap by this number, so old heat cools down | A cell at 1.000 is 0.61 after 100 frames, 0.37 after 200 |
| `TRACK_GRACE` | `2.0` s | Remember a lost tracking ID for 2 s before declaring the person gone | A person hidden behind a pillar for 1 s keeps the same ID |

### 4.4 Video and web output

| Name | Value | Plain meaning |
| --- | --- | --- |
| `JPEG_QUALITY` | `80` | Picture quality when frames are sent to the browser; lower is smaller and faster |
| `MJPEG_MAX_FPS` | `15` | Never send more than 15 pictures per second to the page |
| `WS_INTERVAL` | `0.5` s | Send the numbers (counts, alert state) to the page twice per second |

### 4.5 Paths (they answer "where is the file?")

These are built with `pathlib.Path`, which is Windows-safe: it uses `\` on Windows and `/`
on Linux, and it joins folders for us.

| Name | Built from | Value on this laptop |
| --- | --- | --- |
| `BASE_DIR` | `Path(__file__).resolve().parent.parent` | `C:\Users\akshaya\Downloads\crowd-analytics` |
| `VIDEO_DIR` | `BASE_DIR / "demo_videos"` | `...\crowd-analytics\demo_videos` |
| `EVIDENCE_DIR` | `BASE_DIR / "evidence"` | `...\crowd-analytics\evidence` |
| `OUTPUT_DIR` | `BASE_DIR / "outputs"` | `...\crowd-analytics\outputs` |
| `ZONES_FILE` | `BASE_DIR / "zones.json"` | `...\crowd-analytics\zones.json` |
| `DB_PATH` | `BASE_DIR / "results" / "crowd.db"` | `...\crowd-analytics\results\crowd.db` |

How `BASE_DIR` works, step by step, with a fake path:

```
__file__            = C:\proj\app\config.py
.resolve()          = C:\proj\app\config.py   (full, absolute path)
.parent             = C:\proj\app
.parent             = C:\proj                 <- this is BASE_DIR
```

Why absolute paths matter: if you start the app from `C:\Windows` instead of the project
folder, `open("zones.json")` would look in `C:\Windows`. `BASE_DIR / "zones.json"` always
points at the project's own file. That is a classic beginner bug, and we avoided it on day
one.

## 5. The placeholder modules in `app/`

Each of these files currently contains **only a two-line docstring** (a text block that
explains the file). Python happily imports a file that only contains a docstring. They are
placeholders so the folder layout is complete and every later step has an obvious home.

| File | Its single job (what it will do) |
| --- | --- |
| `vision.py` | Turn a video frame into a list of people, each with a box and a tracking ID |
| `zones.py` | Read `zones.json` and answer "which zone is this point inside?" |
| `analytics.py` | Turn positions into counts, bottlenecks, dwell time, heatmap and debounced alerts |
| `engine.py` | Run the video loop in a background thread and keep the newest result in memory |
| `db.py` | Save each alert to SQLite so the log survives a reload |
| `main.py` | Define the web routes: page, video stream, status, alerts |

`app/__init__.py` exists only to mark the folder as a package. Example: without it,
`from app import config` can fail on some setups; with it, the import always works.

## 6. `scripts/check_env.py` — function by function

This is not part of the app the panel uses; it is our "smoke test" for the environment.

### `show_versions()`

Prints the version of Python, OpenCV, NumPy, ultralytics and FastAPI.
Why: when something behaves oddly in a review, the first question is always "which
version?". Example output line: `opencv : 4.12.0`.

### `check_config()`

Imports `app.config` and prints three values: `CONF`, `ZONES_FILE`, `DB_PATH`.
Why: it proves the import path works and shows the real paths on this laptop.
Expected: `CONF : 0.35`.

### `check_model()`

Calls `YOLO("yolov8n.pt")`. The first call downloads the weights (about 6 MB). Then it
prints how many classes the model knows.
Why: loading the model is the riskiest part of the setup (internet, disk, compatibility),
so we test it before writing any feature.
Number example: `model ok : yolov8n.pt (80 classes)`. Class number 0 is `person`, which is
the only class we will use.

### `main()`

Calls the three checks in order and prints `ALL CHECKS PASSED`.
Why: the last line is your two-minute check — if you see it, the ground is solid.

### The `sys.path.insert(...)` line at the top

When you run `python scripts\check_env.py`, Python puts `scripts\` first on its search
path, so `from app import config` would fail. The line adds the project root to that search
path. Example: `sys.path` becomes
`["C:\...\crowd-analytics", "C:\...\crowd-analytics\scripts", ...]`, so `app` is found.

## 7. `tests/test_config.py` — function by function

Tests are tiny programs that check other programs. We use the standard library `unittest`,
so nothing extra to install. Each test method name starts with `test_`, which is how the
runner finds it.

### `test_conf_is_the_agreed_value()`

Checks `CONF` is `0.35`. `assertAlmostEqual` allows a tiny floating-point difference.
Why: if someone writes `CONF = 35` (percent instead of fraction), every detection would be
thrown away. This test fails instantly instead of silently breaking the demo.
Example: `assertAlmostEqual(0.35, 0.35)` passes; `assertAlmostEqual(35, 0.35)` fails.

### `test_paths_are_absolute_and_named()`

Checks three things: `BASE_DIR` is absolute, the zones file is called `zones.json`, and the
database sits in a folder called `results` and is called `crowd.db`.
Why: the app will look for these exact names. Renaming a file by accident becomes a red
test, not a mystery.

### `test_zones_file_holds_an_empty_json_object()`

Opens `zones.json` and checks it parses to `{}` — an empty dictionary (0 zones).
Why: it proves the file exists and is valid JSON. Example: `{}` loads as an empty dict;
`{oops}` would raise an error and fail the test.

Run command:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
```

## 8. The three most important lines in this step

1. **`BASE_DIR = Path(__file__).resolve().parent.parent`**
   It finds the project folder from the config file's own location. Never depends on where
   you started the app.

2. **`CONF = 0.35`**
   The one number that controls how picky the detector is. Small number = more boxes
   (and more false ones); big number = fewer boxes (and missed people).

3. **`sys.path.insert(0, str(Path(__file__).resolve().parent.parent))`**
   It lets a script in `scripts\` import code from `app\`. Without it:
   `ModuleNotFoundError: No module named 'app'`.

## 9. Files that are easy to misread

- **`requirements.txt`** is a shopping list of exact versions. `pip install -r
  requirements.txt` rebuilds the same environment on another laptop.
- **`.gitignore`** is not for deleting files. It tells Git "do not save this". Example:
  `.venv/` is about 2 GB; committing it would make the repository huge and slow.
  `*.pt` keeps the model weights out; `*.db` keeps the local alert database out;
  `evidence/` and `outputs/` keep generated photos and videos out.
- **`zones.json` with `{}`** means "zero zones". That is correct for step P0: the operator
  has not drawn any zones yet.
- **`static/vendor/.gitkeep`** is an empty file whose only purpose is to make Git keep an
  otherwise empty folder. Git does not track empty folders.

## 10. What could go wrong (and the fix)

| Symptom | Cause | Fix |
| --- | --- | --- |
| `python` opens 3.13 | The shell uses the laptop default | Use `.\.venv\Scripts\python.exe` or activate first: `.\.venv\Scripts\Activate.ps1` |
| `ModuleNotFoundError: No module named 'app'` | Command run from the wrong folder | `Set-Location C:\Users\akshaya\Downloads\crowd-analytics` first |
| Model download fails | No internet on first run | Connect once; the `.pt` file is cached in the project root afterwards |
| `Activate.ps1` is blocked by policy | PowerShell script execution policy | Run `.\.venv\Scripts\python.exe ...` directly; activating is optional |

## 11. Five questions a panel may ask (with short answers)

1. **Why a virtual environment?**
   It gives this project its own Python 3.12 and its own library versions, so installing or
   upgrading something here cannot break another project on the laptop.

2. **Why Python 3.12 and not 3.13?**
   The project's allowed range is 3.10–3.12 because the vision libraries are tested there.
   We picked the newest allowed version.

3. **Why put every number in one config file?**
   So behaviour can be changed in one place and explained in one sentence. Example: to be
   less sensitive, change `CONF` from 0.35 to 0.50; nothing else needs editing.

4. **What does `CONF = 0.35` actually do?**
   It is the confidence cut-off. A detection survives only if the model is at least 35%
   sure it is a person.

5. **Why is `zones.json` empty?**
   Because zones are created later, by the operator, through the dashboard. An empty JSON
   object is a valid "no zones yet" state, not an error.
